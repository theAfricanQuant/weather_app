Before the explanation

Which format does the app use for its local saved search history?

A result becomes a snapshot

After success, poll_worker converts the result into a HistoryEntry, appends it to the app's history vector, and asks history_service to save the collection. The model type derives Serde traits so the structured data can be written to JSON and read on startup.

The “Export CSV” button follows a separate path. The service flattens multi-day results so each day becomes a row, then writes a timestamped CSV file. Think of JSON as the shop's ledger that can be reopened; CSV is the market receipt you take away for a spreadsheet.

Pythonista lens — persistence has its own failure path: Python code might call json.dump and handle file exceptions around it. Here, the history service returns a result that the app must inspect. Fetching weather successfully does not guarantee that writing to disk succeeded, so the UI reports the two outcomes separately. The Rust structs describe the saved data shape, and Serde handles conversion between those typed values and JSON. CSV is a separate export shape for spreadsheet users, not the app's internal history format.
