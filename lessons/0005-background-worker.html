Before the explanation

In this app, which thread owns the request while the network call is running?

Send work out; send a message back

The app uses a standard-library thread and message-passing channel. The UI builds and validates the request, creates sender/receiver endpoints, sets a loading state, and starts a worker. The worker calls the weather service and sends either a success result or an error string. On a later UI update, poll_worker checks the receiver without blocking.

UI threadBuild request
Worker threadCall blocking HTTP
ChannelSend success or error
UI threadUpdate state

Think of it like sending a runner from the market stall to the depot: the stall keeps serving people while the runner returns with a receipt. This app does not use async/await for HTTP; it uses blocking reqwest inside the separate worker thread.

Pythonista lens — a thread has to receive what it uses: A Python thread can often close over names from its surrounding function, with Python's runtime managing the referenced objects. Rust makes the handoff explicit. The move closure takes ownership of the request and sender so the new thread has values that remain valid while it works. Rust also checks that values crossing the thread boundary satisfy its thread-safety rules. The channel is like a typed dispatch pouch: the worker can send only the message shape declared by WorkerMessage, and the UI checks for a message without waiting.
Pythonista comparison: send worker results through a queue

Assume WeatherResult, WeatherRequestError, and WeatherQueryRequest are types defined elsewhere in the Python app. This Python 3.10+ sketch uses a queue to carry either a result or a specific, app-defined error from a worker thread. Rust's WorkerMessage enum gives those alternatives a named, compiler-checked shape; Python's annotation alone does not enforce the queue contents.

from queue import Queue
from threading import Thread


messages: Queue[WeatherResult | WeatherRequestError] = Queue()


def fetch_in_background(
    request: WeatherQueryRequest,
    messages: Queue[WeatherResult | WeatherRequestError],
) -> None:
    try:
        result = fetch_weather(request)
    except WeatherRequestError as error:
        messages.put(error)
    else:
        messages.put(result)


Thread(
    target=fetch_in_background,
    args=(request, messages),
    daemon=True,
).start()
let (tx, rx) = mpsc::channel();
self.worker_rx = Some(rx);
self.loading = true;

thread::spawn(move || {
    let message = match weather_service::fetch_weather(request) {
        Ok(result) => WorkerMessage::Success(result),
        Err(err) => WorkerMessage::Error(err),
    };
    let _ = tx.send(message);
});
