Map the project

Cargo.toml is Cargo's inventory: package name, Rust edition, and dependencies. Our first src/main.rs is a tiny executable so we can prove the crate builds before adding weather features. The upstream main.rs uses module declarations to bring the app's rooms into its crate, then eframe opens the native window. We will compare that complete app with our own growing version.

let options = eframe::NativeOptions {
    viewport: eframe::egui::ViewportBuilder::default()
        .with_inner_size([1240.0, 840.0])
        .with_min_inner_size([1080.0, 720.0])
        .with_title("Cyber Weather Console"),
    ..Default::default()
};

eframe::run_native(
    "Cyber Weather Console",
    options,
    Box::new(|cc| Ok(Box::new(app::CyberWeatherApp::new(cc)))),
)

This is a trimmed excerpt from the reference app's main.rs. Its job is the front gate: set window options, then pass construction to CyberWeatherApp::new. Think of it like the entrance to a market; it directs you to the right stall without stocking every item itself. Our starter crate will initially print a line in the terminal; we will add the GUI only after the crate structure and Rust basics are clear.

Pythonista lens — entry points and packages: main.rs is the Rust binary's entry point, a little like the file Python runs as a script. Rust does not use Python's if __name__ == "__main__": convention here; the main function is the declared start. Cargo.toml is the package manifest, somewhat like project metadata in pyproject.toml. The key difference today: cargo run compiles the project before launching it, so type and syntax problems can stop us before the window opens.

Try it in your workspace

  1. Open the regular Tuxedo OS Terminal, then move to the course folder with its absolute path. Check the location before creating anything:
    cd "/home/siseng/Documents/08_Personal/programing_languages/Rust/weather_app" && pwd
    The printed path should end with /Rust/weather_app. If it does not, stop and correct the folder before running Cargo.
  2. If there is no Cargo.toml here, ask Cargo to create a binary crate in this existing folder:
    cargo init --bin --vcs none
    This folder already holds our course, so cargo init puts the crate files here; cargo new would make another nested directory. The --vcs none flag leaves Git setup for the later repository lesson.
  3. From that same terminal, open the project folder in Zed:
    zed .
    If zed is not found, open Zed from the app launcher and use File → Open Folder to select this course folder. In Zed's file tree, open src/main.rs. Keeping the folder open lets us move between source, manifest, and HTML lesson without losing the project context.
  4. Back in the terminal, run the starter crate:
    cargo run
    Cargo compiles before it launches the program. If compilation fails, bring me the full message; compiler output is our map to the issue, not a sign that you have failed.
  5. Compare our src/main.rs with the linked reference main.rs. In the reference, name one module that sounds like a service, one that sounds like data, and one that sounds like drawing.
What success looks like: you can say “main launches; app owns the interface; services handle outside work” and point to one file for each.
