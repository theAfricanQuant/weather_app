Add one more city

Today's win: make a small change in the real project, then explain how it reaches the GUI.

How we study as a Pythonista · Zed Vim keys

Before the explanation

You want one more quick-select location. Where should its city and state data go?

The change

Add Boston, Massachusetts as a seventh quick city. It is deliberately small: the data list changes, while the existing loop supplies the button and copies the selection into the input fields. This capstone practices finding the right module instead of rewriting working UI code.

QuickCity {
    city: "Boston",
    state: "MA",
},

Add that entry to QUICK_CITIES and change its declared array length from 6 to 7. Keep the six existing entries in place; the array's declared length must match its number of entries. The geocoder searches US city/state results, so this location fits the app's current limitation.

Pythonista lens — the array length is part of its type: A Python list can grow when you append an item. A Rust array has a fixed length recorded in its type, so [QuickCity; 6] and [QuickCity; 7] are different types. We update both the declared length and the entries so the compiler can confirm they agree. This is a small example of Rust asking us to state a constraint once, then checking it for us. If the length does not match, the compiler points to the mismatch before the app runs.

Your build sequence

  1. Open source/src/models.rs and find QUICK_CITIES.
  2. Change the array length from 6 to 7 and add the Boston entry after the existing cities.
  3. Run cargo check from source/. Fix any type or syntax error before launching.
  4. Run cargo run. Confirm the new button appears and selects Boston, MA.
  5. Use “Get Weather” if you have network access. The request should go through the existing city geocoder and worker flow.
Success criteria: it compiles, the preset button appears, selecting it fills the two text fields, and you can explain why no new drawing method was needed.
Hints after your attempt

draw_quick_city_buttons iterates over QUICK_CITIES, creates each button, sets InputMode::CityState, and copies the selected city and state into app state. The existing draw method handles the new item automatically.
