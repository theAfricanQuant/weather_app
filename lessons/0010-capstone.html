Pythonista lens — the array length is part of its type: A Python list can grow when you append an item. A Rust array has a fixed length recorded in its type, so [QuickCity; 6] and [QuickCity; 7] are different types. We update both the declared length and the entries so the compiler can confirm they agree. This is a small example of Rust asking us to state a constraint once, then checking it for us. If the length does not match, the compiler points to the mismatch before the app runs.
Pythonista comparison: grow a list

Assume QuickCity is defined elsewhere in the Python app. On Python 3.9+, this type hint describes a list whose items are QuickCity values. A Python list can grow when an item is appended; Rust's fixed-size array records its length in its type.

quick_cities: list[QuickCity] = [
    QuickCity(city="Boston", state="MA"),
]
quick_cities.append(
    QuickCity(city="Chicago", state="IL"),
)

Code along: add one city and let the compiler check the array

Create src/bin/lesson_10.rs and paste this complete program. It is a tiny console version of a preset-city list, so you can see the fixed array length rule before comparing it with the GUI reference.

#[derive(Debug)]
struct QuickCity {
    city: &'static str,
    state: &'static str,
}

const QUICK_CITIES: [QuickCity; 4] = [
    QuickCity {
        city: "Boston",
        state: "MA",
    },
    QuickCity {
        city: "Chicago",
        state: "IL",
    },
    QuickCity {
        city: "Denver",
        state: "CO",
    },
    QuickCity {
        city: "Seattle",
        state: "WA",
    },
];

fn main() {
    for (index, city) in QUICK_CITIES.iter().enumerate() {
        println!("{}. {}, {}", index + 1, city.city, city.state);
    }
}

Run cargo run --bin lesson_10. Then add one QuickCity entry and change the declared length from 4 to 5. Run it again. If you change only the number, Rust reports that the array length and entries do not match. Python's list would grow dynamically; Rust checks the fixed count in the array's type.
