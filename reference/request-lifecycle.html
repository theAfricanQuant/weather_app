Happy path

1 · UI inputdraw_inputs reads strings and mode.
2 · Typed requestbuild_request validates and creates WeatherQueryRequest.
3 · Worker threadstart_fetch moves the request into a thread.
4 · LocationCity/state is geocoded; coordinates are range-checked.
5 · Weather APIChoose archive, forecast, or both for a crossing date range.
6 · Internal recordsDeserialize JSON and build daily records with optional fields.
7 · Message returnSend Success(result) through mpsc.
8 · UI updateStore result, choose animation, save history, and draw next frame.

Where errors appear

  • Input validation: a bad date, reversed range, empty location, or non-numeric coordinate returns a user-readable Err before the worker starts.
  • Geocoding: network, HTTP status, JSON parsing, and missing result errors become a worker error message. The current city/state search is US-only.
  • Weather request: network/status failures and malformed JSON become a worker error message.
  • Persistence: weather can load successfully while history saving fails; the status message reports that difference.

The key habit: follow the returned Result value to its caller. An error does not teleport away; each boundary decides how to report or recover from it.
