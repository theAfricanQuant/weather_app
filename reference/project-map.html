Rusty Weather project map

Use this page to orient yourself before opening a source file.

Top-level path

src/
├── main.rs                 // module list and native app startup
├── app.rs                  // GUI state, input, worker messages, rendering
├── models.rs               // request, response, history, and UI types
├── date_utils.rs           // parse and format date values
├── geocoding_service.rs    // US city/state to coordinates
├── weather_service.rs      // Open-Meteo request and response mapping
├── weather_code_map.rs     // weather codes to readable labels/modes
├── history_service.rs      // local JSON and CSV export
└── animation.rs            // weather visuals

Source references: src directory and Cargo manifest.

Who owns each job?

main.rsBuilds native window options and starts eframe.
models.rsNames the data that crosses module boundaries.
app.rsOwns live UI state and coordinates the user's actions.
ServicesHandle network requests and local persistence.

Analogy: main.rs is the market entrance, app.rs is the central desk, and the service modules are specialist stalls. The shared models tell each stall what shape of request or result to expect.

One request at a glance

1 · InputStrings and selected mode in app state.
2 · ValidateDates, city/state or parsed coordinates.
3 · WorkerBlocking network work runs off the UI thread.
4 · NormalizeJSON becomes internal weather records.
5 · ReturnA message channel delivers success or error.
6 · PresentUpdate result, history, animation, and status.
